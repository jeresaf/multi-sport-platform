# Backend conventions (.NET 10)

## Module layout
- `Modules/<Name>/SportsPlatform.Modules.<Name>/` → `Domain/`, `Features/<Area>/<UseCase>/`, `Infrastructure/`
  (DbContext, EF configurations, `Migrations/`), `Seed/`, `<Name>Module.cs`.
- `Modules/<Name>/SportsPlatform.Modules.<Name>.Contracts/` → the only project other modules may reference:
  query interfaces, approved command interfaces (imports/seeds), DTOs, integration events, scope-chain provider.
- Create a module only when its first slice starts. Keep BuildingBlocks tiny and free of business logic.

## Adding a use case
1. Folder `Features/<Area>/<UseCase>/` with request, handler, validator (FluentValidation for request shape),
   endpoint mapping and response DTO.
2. Endpoint declares exactly one action: `.RequireAction(<Module>Actions.X)` (or `.AllowPublic()` for public reads).
3. Handler loads the aggregate, calls a domain method, saves. Expected failures → `Result.Failure(<Module>Errors.X)`.
   The endpoint returns `result.ToHttpResult(...)` (Problem Details with the error's `code`).
4. Integration events for other modules go to the outbox in the same transaction.
5. Map entities → DTOs with explicit code (no AutoMapper). Never return entities.

## Domain
- Aggregates enforce invariants through methods; no public setters for state that has rules.
- Status changes go through the canonical state machines (docs/domain/state-machines.md); exceptional
  transitions require a reason parameter.
- `Domain/` must not reference EF Core or ASP.NET Core (architecture test).
- Use `TimeProvider` and IDs from the base entity (`Guid.CreateVersion7()`); never `DateTime.Now`.

## Cross-module
- Inject other modules' Contracts interfaces only. Validate referenced IDs through them (no cross-module FKs).
- React to other modules through integration events; consumers must be idempotent (inbox).
- Never branch on sport codes; use `ISportDefinitions`, `IScoringEngines`, `IFormatGenerators`.

## Declarations (generated into docs/generated by the CLI)
- Actions: `<Module>Actions` (code, description, scope, scopable-by, audit, entitlement, idempotent).
- Errors: `<Module>Errors` (`<AREA>_<CONDITION>`, HTTP status, default message).
- Integration events: records in Contracts, past tense, versioned (`ResultApproved.V1`).

## Tenancy and privacy
- Tenant-owned entities implement `ITenantOwned`; the interceptor stamps `TenantId` — never assign it from input.
- No `IgnoreQueryFilters()` in features. Platform-wide reads only in explicitly named platform services.
- Annotate personal-data properties with their classification; never log `PRIVATE`/`SENSITIVE` values.

## Style
- Nullable enabled; warnings are errors; async all the way with `CancellationToken`.
- Structured logging with message templates and IDs (no string interpolation in log calls); prefer
  `[LoggerMessage]` methods. Don't add `CorrelationId`, `TenantId`, `ActorKind` or `ActorId` yourself: every
  request's events get them (`RequestContextEnricher`). `ITenantContext`/`ICurrentActor` must not log while being
  resolved.
- Prefer small, explicit code over clever abstractions; no MediatR, AutoMapper, MassTransit or other
  commercially licensed packages (ADR-0013).
